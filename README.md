# מערכת ניהול אירועים — טכנודע

טופס ניהול אירוע ממוחשב (על בסיס `tofes.xlsx`) עם שרשרת אישורים:

```
מגיש/ה → קב"ט (עזריאל) → משנה למנכ"ל (אמילי) → סמנכ"ל תפעול (דינה) → זימון ליומן
```

- כל שלב חותם בציור (אפשר לשמור חתימה לפעם הבאה) או מחזיר לתיקון עם סיבה.
- אחרי תיקון, האירוע חוזר **ישירות לשלב שהחזיר אותו**. למשל, דינה מחזירה לשינוי מועד, והאירוע המתוקן חוזר אליה.
- בשלב של דינה מוכנה טיוטת זימון: נושא, תאריכים, שעות, מיקום, תוכן ונמענים. היא יכולה לערוך הכול. באישור, הזימון נשלח מ-Google Calendar ומגיע ל-Outlook כזימון רגיל.
- התראות במייל בכל מעבר שלב: למאשר/ת הבא/ה, וליוצר/ת בהחזרה ובאישור הסופי.
- משימות: כל אחראי/ת בטופס רואה בלשונית "המשימות שלי" את מה שעליו/ה ומסמן/ת "בוצע".
- לוח מצב, זיהוי אוטומטי של אירועים חופפים או נושקים, שכפול אירוע, וייצוא PDF (הדפסה).
- עמדת ניהול: עובדים (Gmail לכניסה ומייל עבודה), תפקידים, ומוזמנים קבועים לזימון.

## קבצים

| קובץ | תפקיד |
|---|---|
| `index.html`, `style.css` | המסכים |
| `app.js` | כניסה, ניתוב, טופס, אישורים, משימות, לוח מצב |
| `admin.js` | עמדת ניהול |
| `template.js` | תבנית ברירת המחדל (חלקים א'–ג' מהאקסל) ורשימת עובדים התחלתית |
| `store.js` | שכבת נתונים: Firebase, או מצב הדגמה בדפדפן |
| `mail.js` | מיילים (EmailJS) וזימונים (Apps Script) |
| `signature.js` | משטח חתימה |
| `calendar.gs` | הקוד שרץ ב-Google Apps Script ויוצר את הזימון |
| `database.rules.json` | כללי אבטחה ל-Firebase |

## מצב הדגמה

כל עוד `FIREBASE_CONFIG.apiKey` ב-`config.js` ריק, המערכת רצה במצב הדגמה. מסך הכניסה מאפשר לבחור כל עובד/ת, כך שאפשר לעבור על כל השרשרת לבד. מיילים וזימונים לא נשלחים: הם נאספים בכפתור "📬 דואר הדגמה". כדי להריץ מקומית, מפעילים שרת קבצים פשוט בתיקייה (למשל `npx serve`) ופותחים את הכתובת בדפדפן.

## הפעלה אמיתית

1. **Firebase**: ב-console.firebase.google.com יוצרים פרויקט חדש (מומלץ נפרד ממערכת החופשות).
   - Authentication → Sign-in method → Google → Enable
   - Authentication → Settings → Authorized domains → להוסיף `snirsnir.github.io`
   - Realtime Database → Create (europe-west1) → Rules → להדביק את `database.rules.json` → Publish
   - Project settings → Your apps → Web → להעתיק את ה-config ל-`FIREBASE_CONFIG` ב-`config.js`
2. **Apps Script** (זימונים): לפי ההוראות בראש `calendar.gs`. ממלאים את `APPS_SCRIPT_URL` ואת `APPS_SCRIPT_TOKEN` ב-`config.js`. הזימון יוצא מהיומן של החשבון שמריץ את הסקריפט.
3. **EmailJS**: מוגדר עם אותו שירות ואותה תבנית של מערכת החופשות. אין צורך לשנות.
4. **GitHub Pages**: מעלים את התיקייה ל-repo `event` ומפעילים Pages. הכתובת תהיה `https://snirsnir.github.io/event/` (מוגדרת ב-`SYSTEM_URL`).
5. **כניסה ראשונה**: הכניסה הראשונה צריכה להיות עם `snirdoani@gmail.com` (`BOOTSTRAP_ADMINS`). היא טוענת את רשימת העובדים ההתחלתית, ומשם מנהלים הכול מעמדת הניהול.

## הערות

- הנתונים פתוחים לקריאה ולכתיבה לכל עובד/ת פעיל/ה במערכת. האכיפה של "מי מאשר מה" נעשית בממשק. לארגון פנימי זה מספיק. אם בעתיד צריך אכיפה בשרת, מוסיפים Cloud Functions.
- בחלק ב' כתוב "יש לצרף הנחיות קב"ט עירוני". צירוף קבצים לאירוע הוא שלב המשך (Firebase Storage).
